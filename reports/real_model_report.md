结论：默认使用 deepseek-flash。它的问题都是格式类，程序能确定地修正；gemini 的过度推断属于内容问题，质检规则难以识别。
为此 SKILL.md 已补充约束：纪要只提到相关事实、未说明与销售变化的关系时，写“可能与此有关，具体影响待核实”，
摘要中的原因不得比异常分析更确定；影响金额是整个异常对象的变动，不得说成带动门店的合计。

### 验证中发现并已修复的程序问题

| 问题 | 修正 |
|---|---|
| 模型写门店名不带编码 | 程序在带动门店第一次出现处补编码；识别简称（“徐汇”）和自带括号的写法（编码并入括号） |
| 压缩篇幅时漏写带动门店，修正轮次耗尽 | 程序把漏写的带动门店补在“现象”末尾；压缩提示要求保留门店名 |
| 涨跌词与数字之间隔几个字时漏检（“拉低华东区实收 -26,898 元”） | 检查允许中间隔字，并加入拉低 / 拉高 / 拖累 |
| 占位符后重复写单位（“203,120 元 元”） | 替换后自动合并 |
| 页数估算偏差 | 用 56 份报告与 Word 实际页数对比，每页底部预留取 0.15 英寸：无估少，1 份估多 |

### 仍需人工关注

- 影响金额归属是否正确（如把区域变动说成两家门店的合计）质检无法判断，靠岗位说明约束和审核人把关。
- 页数为按版式估算，已用官方数据第 42～44 周的报告校准；数据规模明显不同时建议抽查 Word 实际页数。
